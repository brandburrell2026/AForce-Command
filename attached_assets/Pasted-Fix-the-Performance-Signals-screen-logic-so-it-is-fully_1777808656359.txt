Fix the Performance Signals screen logic so it is fully state-driven by one hydration score algorithm.

Current issue:
The screen can show conflicting states, for example:
- Hydration signal shows CRITICAL
- Symptoms are selected
- Energy state shows LOW
- But Current Score still shows 100 / PEAK

This is incorrect.

Goal:
Make the screen calculate the Current Score dynamically from all selected inputs and logged data.

One source of truth:
getHydrationScore(inputs)

The Current Score, hydration signal status, energy state, colors, labels, AI Coach commands, and confirm button must all update from the same score output.

Required logic:

1. Selected symptoms must reduce score:
Headache = -8
Muscle cramp = -12
Fatigue = -10
Lightheaded = -18
Dry mouth = -14
Low focus = -8

2. Urine color / hydration signal must reduce score:
Level 1 = -0
Level 2 = -2
Level 3 = -5
Level 4 = -10
Level 5 = -16
Level 6 = -22
Level 7 = -28
Level 8 = -35

3. Energy state must reduce score:
PEAK = -0
STEADY = -5
LOW = -15
CRASHED = -30

4. Score should recalculate instantly when user selects:
- Symptoms
- Hydration signal level
- Energy state
- Water logged
- AForce product logged
- Gender
- Height
- Weight
- Activity level
- Weather
- Workout status

5. Scoring order:
Start at 100
Subtract symptom penalty
Subtract urine color penalty
Subtract energy state penalty
Subtract thirst penalty
Subtract activity/weather/workout penalty
Add recent water boost
Add AForce product boost
Add hydration cycle boost
Clamp score between 0 and 100

6. Status mapping:
85–100 = OPTIMAL / PEAK
70–84 = STABLE / STEADY
50–69 = DECLINING / LOW
30–49 = RISK
0–29 = CRITICAL / CRASHED

7. Color mapping:
OPTIMAL = neon green
STABLE = lime green
DECLINING = amber
RISK = orange
CRITICAL = red

8. Important UI behavior:
If hydration signal is Level 7/8, score cannot remain 100.
If Lightheaded + Dry Mouth + Low Focus are selected, score cannot remain 100.
If Energy State is LOW, score cannot remain 100.
If several risk signals are selected, the score must fall into DECLINING, RISK, or CRITICAL.

9. Current Score card must display:
- Final calculated score
- Status label
- Reason summary
- Top 3 active signals

Example:
Current Score: 42
Status: RISK
Reason: Hydration risk elevated from urine color, dry mouth, and low energy.
Signals:
- Urine color elevated
- Dry mouth selected
- Energy state low

10. Confirm Status button:
When clicked, save the selected signals and calculated score.
Then route to AI Coach screen with the exact score output.
The AI Coach screen must not recalculate differently.
It should receive the same score object.

11. Debug mode:
Add a hidden developer/debug panel that can show:
- symptomPenalty
- urinePenalty
- energyPenalty
- riskPenalty
- waterBoost
- aforceBoost
- finalScore

This will help verify the screen is calculating correctly.

Final requirement:
Remove all hardcoded “100” score states.
The score must always come from getHydrationScore(inputs).
