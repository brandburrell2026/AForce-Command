Redesign the AForce OS Home Screen into a true “One-Command OS” interface.

IMPORTANT:
This is not a dashboard.
This is not a multi-feature screen.

This is a decision engine.

The screen must deliver:
ONE CLEAR COMMAND
in under 1 second.

Everything else supports that command.

==================================================
CORE PRINCIPLE
==================================================

If the user looks at the screen for 1 second, they should know exactly:

1. Their state
2. What to do
3. Why it matters

No thinking.
No scanning.
No confusion.

==================================================
REMOVE THESE ISSUES FROM CURRENT DESIGN
==================================================

- Multiple competing command blocks (AI Command + AI Coach duplication)
- Repeated instructions (“Correct now”, “Drink now” multiple times)
- Too many red containers competing for attention
- Timer with unclear meaning (00:00 confusion)
- Overloaded top section
- Too many equal-weight UI sections

==================================================
NEW STRUCTURE (STRICT HIERARCHY)
==================================================

Build the screen in this exact order:

--------------------------------------------------

1. SYSTEM ALERT (ONLY IF CRITICAL)
- Show Heat Guard ONLY if urgent
- Keep it thin, not dominant
- Example:
“Heat Risk Rising — Begin cooling”

--------------------------------------------------

2. CORE STATE (THE ORB)
- Large center orb
- Show:
  - Score (large)
  - State (Depleted / Recovering / Balanced / Peak)
- Orb MUST be animated based on state:
  - Depleted = unstable / broken pulse
  - Recovering = slow contraction
  - Balanced = smooth breathing
  - Peak = energetic pulse

This is the identity of the product.

--------------------------------------------------

3. PRIMARY COMMAND (MOST IMPORTANT ELEMENT)

This must dominate the screen.

Large container.
High contrast.
Impossible to miss.

Structure:

[ HIGH PRIORITY ]

Drink 16 oz now  
+ 1 AForce stick  

Recheck in 25 minutes  

[ PRIMARY CTA BUTTON ]
Log Intake

Below:
Projected: +12 to score

RULES:
- One command only
- No duplicate phrasing
- No secondary commands nearby

--------------------------------------------------

4. WHY (MINIMAL CONTEXT)

Small, clean, secondary block.

Example:

Why:
- Overnight deficit: 14 oz
- 4-day compliance streak

Keep it short.
No paragraphs.

--------------------------------------------------

5. QUICK ACTION (OPTIONAL, LOW PRIORITY)

Inline icons (small):

Water | Stick | RTD

Must NOT compete with primary CTA.

--------------------------------------------------

6. SYSTEM SIGNAL (CONDENSED)

Combine all of this into ONE LINE:

Core temp • HRV • Mode • Status

Add interpretation:

“Stable for light training”

--------------------------------------------------

7. HARDWARE (PHANTOM BAND)

Keep subtle:

“Phantom Band connected”

Do NOT make it a large section.

--------------------------------------------------

8. REMOVE OR REDUCE

- AI Coach duplication (must not repeat command)
- Extra red blocks
- Multiple containers
- Any secondary CTA competing with main action

==================================================
COMMAND DESIGN RULES
==================================================

The command must be:

- Direct
- Specific
- Actionable
- Time-bound

DO NOT USE:
- “try”
- “consider”
- “correct now”
- “you may want to”

USE:
- “Drink 16 oz now”
- “Take 1 AForce stick”
- “Recheck in 25 minutes”

==================================================
VISUAL DESIGN RULES
==================================================

- Dark premium background
- Red only for urgency
- One dominant card only
- Reduce borders
- Increase spacing
- Use glow for primary command
- Orb must feel alive
- Smooth motion transitions

==================================================
INTERACTION FLOW
==================================================

When user taps “Log Intake”:

1. Instant feedback
2. Score increases
3. Orb stabilizes
4. Color shifts (red → amber)
5. New state appears
6. New command generated

Must feel:
instant, rewarding, controlled

==================================================
SUCCESS STATE (AFTER ACTION)
==================================================

Show briefly:

+12 Score  
Back in control  

Then return to updated home state

==================================================
FINAL EXPERIENCE GOAL
==================================================

User should feel:

“I don’t need to think.  
I just follow the system.”
